# Mixed-batch bench

## Scope and boundaries

The goal is to handle images and videos of differing temporal lengths and spatial sizes in one batch, correctly and as efficiently as possible. A *document* is one independent sample; an image is a 3-D document of temporal length 1. Cases are organized by capability, and each says what error it can expose; its parameters exist to trigger a mechanism.

The implementation frozen for the first round is the one that had just gained per-document degenerate-axis lowering for heterogeneous packs and did not yet dispatch them in a single launch; every kernel fix after it is accounted for separately against that baseline. What a pass covers is what each check defines for itself: a composite PASS over the generated graphs is not a migration acceptance gate.

Qualification boundary: with BF16 dQ and dK zeroed out entirely, all six property classes still PASS over the same batch of generated graphs, although the independent reference gradients are nonzero. A composite PASS is therefore not sufficient as a full migration gate, and the bench is for diagnosis and regression. The next paragraph's real-dtype gradient comparison closes that gap; fault injection for a fully wrong call is still missing.

The [real-dtype gradient comparison](https://github.com/SHI-Labs/NATTEN/blob/main/tests/test_varlen_gradients.py) runs from all three entry points: ordinary pytest, `properties` and `contracts`. Its inputs have zero logits but nonzero Q/K derivatives; the neighborhood sizes are 1, 2, 4 and 8, so the inputs and the expected gradients are exactly representable and are compared with zero tolerance. FP32/FP16/BF16 by three ranks, plus three broken-gradient counterexamples: 12 items. This is the positive control for that class of lost gradient; it does not replace numerical-error attribution over arbitrary random inputs. The logsumexp path's contract and non-contiguous inputs are covered by ordinary tests as well.

Ordinary pytest continues to serve the fix phase: the large-magnitude identity check also covers partial gradients, shared KV heads, differing QK and V head dimensions, non-contiguous inputs and a compiled backward, 37 items in the gradient test file altogether. The [dot-product check](https://github.com/SHI-Labs/NATTEN/blob/main/tests/test_compute_delta.py) uses exactly representable FP64 answers to detect premature rounding, overflow and underflow in the multiply; the [whole-axis window check](https://github.com/SHI-Labs/NATTEN/blob/main/tests/test_varlen_uniform_dispatch.py) verifies that stride does not change a neighborhood already covering the axis; the [cache check](https://github.com/SHI-Labs/NATTEN/blob/main/tests/test_varlen_layout.py) varies stride and the causal flags and restores the original arguments, requiring output, logsumexp and Q/K/V gradients to be bitwise identical between a reused cache and a freshly built layout. Each run keeps its per-item readings in its artifacts; see Running it below.

Entry points: the [runner](https://github.com/SHI-Labs/NATTEN/blob/main/scripts/bench_mixed_batch.py); the [generic properties and graph generator](https://github.com/SHI-Labs/NATTEN/blob/main/tests/mixed_batch_properties.py); the [independent reference and fixed regression set](https://github.com/SHI-Labs/NATTEN/blob/main/tests/mixed_batch_utils.py); the [known answers and fault injection](https://github.com/SHI-Labs/NATTEN/blob/main/tests/test_mixed_batch_bench.py) that put the instrument itself on duty. The caller names the result directory, and an existing one is refused rather than overwritten.

## Generic properties are the main line

The first, case-by-case version is now the fixed regression set. The main line generates attention graphs and verifies mathematical properties that do not depend on any particular fault; known faults prove the checker catches something, they do not define the coverage.

A mixed batch is the union of several independent documents' attention graphs. A graph records the query and key logical coordinates, the permitted edges, and the query-to-KV head mapping. The generator emits small graphs straight from that specification and encodes them as the public API's layout and arguments; it never looks at the operator's output and never discards an input for failing. Each round is 24 graphs covering different ranks, boundaries, windows, sparsity patterns and head mappings, at most 96 tokens per graph so the whole graph can be checked. The structural coverage actually reached is written to `graph-coverage.json`.

| Property | Generic check | Errors it finds |
| --- | --- | --- |
| Graph connectivity and weights | With Q/K = 0, encode every key at once in V's basis vectors and read the whole adjacency matrix off the output; then encode every query in dO's basis vectors and read each Q head's complete backward graph to the KV heads | Extra or missing edges, boundary and causal errors, cross-document leakage, head mapping errors, wrong normalization; forbidden edges are required to be zero and permitted ones to carry signal |
| Gradient dependence on random data | Q, K and V all nonzero; project the loss onto one query at a time and check the other queries' dQ and every forbidden key's dK/dV | Covers the blind spot a zero-logit probe leaves in the Q/K backward; every query is checked separately, since nonzero gradients under a simultaneous backward cannot rule out causal leakage |
| Batch composition | The same graph union called per document, packed, reordered and restored, with empty documents inserted, and with one document perturbed | Packing, offset, permutation and state-reuse errors; images and videos are just instances of the generated graphs |
| VJP linearity | For any generated graph and random loss direction, compare the backward results for a zero upstream gradient, a negated one and a doubled one | Uninitialized or leftover gradients, wrong gradient scaling, a nonlinear backward; the transforms are exactly representable so they add no input quantization of their own |
| Forward/backward consistency | Central finite differences along random directions in Q, K and V, checked against the backward's projection; two fixed step sizes cross-check each other | A backward implementing the wrong derivative, a missing scale or path, a sign error -- and it does not rely on two optimized kernels vouching for each other when they share a fault |
| Numerical representability | Constant V on any graph, fixed upstream gradient, varying only V's binary magnitude; the correct output is that constant, the Q/K derivatives are zero in real arithmetic, and the V derivative follows from the graph | Non-finite contamination independent of token count or any known overflow value; algebraic cancellation error is reported alongside |

The connectivity check's zero support is strict. Its coefficient scale is calibrated from an independent CUDA division, `exp(-log(degree))` and the output rounding at the same graph degree and dtype, with one output ULP allowed on top; that is the scale of a single normalization computation, not a general error bound for attention.

The VJP zero and sign relations are checked strictly. The doubling relation checks whether the two final outputs' rounding intervals are compatible: with `r(g)` the gradient dtype's half ULP at `g`, it requires `|g2 - 2*g1| <= 2*r(g1) + r(g2)`, and the bitwise difference is kept. Self-check correction: requiring the output to scale bitwise merely because the transform was a doubling missed FP16 subnormals' final rounding; a correctly rounded but not bitwise scaled positive case and an out-of-interval negative case were added. That correction applies to this property only and does not relax the existing packed-versus-isolated or single-key acceptance.

Finite differences check local derivatives on FP32 only. The interval records four terms separately: the operator forward's error against FP64 on the same perturbed inputs, the FP64 finite difference's truncation and input-rounding error against its own autograd, the gradient output's rounding unit, and the backward's own internal arithmetic. Every GEMM in the FP32 kernels runs `OpMultiplyAddFastF32` (3xTF32: each operand is split into two TF32-sized parts and three TF32 multiply-adds approximate one FP32 multiply-add, each product within `2^-22` relative error), not IEEE FP32; the internal arithmetic term is the cost of that layer, taken as `2 * |a_3x - a_ref|`, where `a_3x` is the directional derivative from a CPU 3xTF32 emulation of the dense backward on the same inputs (all six matrix products -- `QK^T`, `PV`, `dO V^T`, `dS K`, `dS^T Q`, `P^T dO` -- in 3xTF32, elementwise operations in FP32). The interval is still not fitted to the backward under test: that term comes from an independent emulation, and it still catches a missing scale, a wrong sign or a wrong path. General forward correctness remains constrained by the independent reference and the other properties; a self-consistent derivative alone does not prove the function correct.

The three criteria below were set after attributing each reading item by item -- four readings once recorded as numerical failures, none of which turned out to be a logic error:

- **The FP16 doubling relation** is taken at a cotangent scale that does not fall into FP16 subnormals. Reconstruct this graph's `dS * scale` (the quantity the kernel stores in shared memory) densely in FP64, take the smallest `k` in `[0, 12]` for which every nonzero entry satisfies `|dS * scale| * 2^k >= 2^-13` and the doubled output stays bounded (`<= 2^14`), and compare the whole group with the upstream gradient scaled by `2^k`. When no such `k` exists the case records `NOT_APPLICABLE` with the dynamic range that ruled it out, not a FAIL. BF16 has FP32's exponent range, so `k` is always 0 there and for FP32. The GQA comparison is made after expansion to each Q head (the test first `repeat_interleave`s K/V to `heads`), so that a Python-side sum over KV heads cannot amplify one head's sub-ULP perturbation into a full ULP. Positions where the FP64 reference gradient is exactly zero (single-key rows) are excluded from the doubling comparison and bounded by the single-key gate below instead: `|dQ_rhd| <= c_max * scale * |K_jhd|` plus one output half ULP, where `c_max` is that gate's `|c_h / scale|` bound, and dK sums over all single-key rows pointing at that key. Reference zeros not explained by a single-key row are still required to be exactly zero. The zero and negation relations stay strict.
- **Single-key row acceptance splits by path.** A heterogeneous pack runs in one launch and clamps each document's window inside the CUDA kernel, so the Python identity path is taken in exactly one situation: the *whole call*'s effective kernel is 1 on every axis -- clamped by `min(kernel, extent)` when the layout is uniform (an axis with `kernel_size > 1` and `dilation > 1` is not clamped), and read off the caller's own `kernel_size` when it is not. Such a call launches no attention kernel and keeps bitwise zeros and bitwise equality. Every other single-key row, including a fully degenerate document inside a heterogeneous pack, is computed in the kernel: O and dV stay bitwise on FP16/BF16, and FP32 allows O `2^-21 * |V| + 2^-30` (the cost of `1 * V` under 3xTF32). FP32 dV takes that same product interval on `|dO|` widened by `|dO| * q(b)`, because the backward does not reuse the forward's softmax weight: it recomputes `P = exp(S * scale - lse)` from a transposed GEMM whose score differs from the forward's by a few ULP, so the weight arrives as a float32 neighbour of 1.0 rather than the exact `exp(0) = 1` the forward had, and `dV = P * dO` misses the `1 * dO` product by `(P - 1) * dO`. `b` is `single_key_scalar_bound` on that row's scaled score `q * k * scale` -- the same two-summation-path bound the dQ/dK residual already takes, the score likewise being summed once forward and once transposed -- and `q(b)` carries a bound on the exponent over to one on `|P - 1|` for a float32 next to 1.0: `0` when `b < 2^-25`, where `1 + eps` rounds back to exactly 1.0 in every case (the half spacing is `2^-24` above 1 and `2^-25` below), and `b + 2^-24`, the bound plus the largest rounding step near 1, otherwise. No new tolerance enters: the forward keeps its own interval, since its weight is exactly 1, and FP16/BF16 spacing is coarser than the whole deviation, so they keep the bitwise gate. dQ and dK must be exactly zero outside the focus row and key row, and the row itself is fitted per head to a scalar `c_h` by FP64 least squares, required to reconstruct the row (bitwise on FP16/BF16, within the same 3xTF32 interval on FP32) and to satisfy `|c_h / scale| <= 8 * ulp32(P) + 2^-21 * sum_d |dO_d * V_d|`, where `P` is the largest absolute sequential prefix sum of `sum_d dO_d * V_d` and the second term is the 3xTF32 per-product error, counted for FP32 only (FP16/BF16 products are exact in the FP32 accumulator). `c_h`, the bound and the bitwise hit count all go into the result, so a failure stays diagnosable. Under GQA, dV is what the Python-side `repeat_interleave` backward gets by summing each Q head's 3xTF32 products, and each term's error is proportional to its own magnitude, so the FP32 interval is built on `sum_h |.|` before the sum rather than on `|sum_h .|` after cancellation.
- **Packed versus isolated comparison splits by lowering.** A document with an extent-1 axis on which the caller's `kernel_size > 1` (and `dilation = 1`) has a uniform layout when called alone: Python folds or permutes that axis away and the call lands on a lower-rank kernel, or on the identity path. The same document inside a mixed pack has its window clamped by the kernel. The two are two implementations of one mathematics and are no standard for each other, so each is compared against one common FP64 dense reference instead: per tensor (O, LSE, dQ, dK, dV) it requires `max|packed - ref64| <= 2 * max|isolated - ref64| + 1 ulp`, with the ULP taken at the reference magnitude where the packed error peaks. Where such a document's effective kernel is 1 on every axis, its isolated call takes the identity path and is exact, `2 * max|isolated - ref64|` degenerates to zero, and O/dV/dQ/dK fall to the kernel single-key gate above row by row; LSE (a single-key row is `scale * q * k`, summed in float32 in a different order on each side, with the packed side going through 3xTF32 on FP32) is bounded by the same expression applied to `q * k` and multiplied by `|scale|`. Every other document stays bitwise. This rule governs all packed-versus-per-document comparisons, performance loads included, which are adjudicated per document the same way. Packed-versus-packed comparisons -- repeated runs, reorder and restore, empty insertion, perturbing another document, document independence -- stay bitwise throughout.

**Structural zeros** and **zeros from algebraic cancellation** are distinguished: with no dependency edge the result must be exactly zero, while the finite residual of an algebraic identity such as constant V is reported separately instead of being called a mask error.

These property checkers take an operator call function and can be reused for other sparse attention implementations; a migration replaces the graph encoding and the call adapter and keeps the properties. Changing `--graph-seed` generates graphs that took no part in choosing the fixes; a fixed seed is for regression. The generic properties currently run on the eager CUTLASS path, and compile and execution modes are covered by the separate contracts group.

## What the fixed regression set maps

| Capability | Representative scenario | Check, and what a failure means |
| --- | --- | --- |
| Sample independence | Interleaved images and videos, mixed lengths; modify one document only | The other documents' outputs and gradients are strictly unchanged; with the backward taken through one document only, the others' gradients are strictly zero |
| Mixing does not change semantics | The same Q/K/V and upstream gradient, packed and called per document | Each document's O, dQ, dK and dV are compared under the rule its isolated lowering selects (see Packed versus isolated comparison splits by lowering); repeated runs on both sides calibrate the noise; nondeterministic loads follow item 3 of Three layers of readings |
| Order and empty samples | Reorder the documents and restore, insert empty documents, make them all empty | Results are identical once restored; an empty document contributes no token, and an all-empty pack still backpropagates |
| Temporal causality and neighborhood boundaries | First, middle and last frame; positions outside the local window and positions skipped by dilation | An independent coordinate mask checks that unreachable K/V gradients are zero and that modifying unreachable K/V does not change the target output; reachable positions are kept as the positive control |
| Spatial semantics | 2-D and 3-D; per-axis causality, non-square and unequal axis lengths | Explicit FP64 neighborhood reference, so that more than the temporal mask is checked; a spatial neighbor in the same frame must not be mistaken for the future |
| Degeneracy and clamping | Images with T = 1, H = 1, W = 1, single-token documents; axis length below, equal to and above the window | Single-key `O = V`, `dQ = dK = 0`, dV routing; the difference between a 3-D image and its isolated call is checked |
| Explicitly non-mixing axes | `kernel_size = 1` on the first, a middle and the last axis, and on several axes | Coordinates and gradients are checked after the fold, permute and restore, so more than the contiguous-view path is covered |
| Generalized neighborhoods | Even windows, stride groups with an incomplete final group, dilation residue classes | A hand-written neighbor table validates the reference first, then the operator's forward, backward and unreachable positions are checked |
| Head and tensor layouts | MHA/GQA/MQA, differing QK and V head dimensions, non-contiguous inputs | KV head gradients must aggregate the corresponding Q heads; values are compared against the contiguous call, and output shape and order must be right |
| Numerical edges | FP32/FP16/BF16; zero QK, constant V, saturated logits, product overflow and underflow, cancellation | Exactly representable known answers on finite inputs; the delta dot product is verified separately; general error is reported per document and per tensor |
| Execution capability | Eager, inference, partial gradients, deterministic mode, multiple streams, cold and warm layout, fullgraph and AOT, layout changes | Reuses the existing mechanism tests and records pass/fail/skip/error per item; compiling successfully does not substitute for correct gradients and layout reuse |
| Input contracts | Mismatched shape, dtype or device, invalid head counts, invalid geometry, int32 boundaries, explicit tile and split limits | Reuses the API, layout and raw-op checks; valid inputs succeed and invalid ones are rejected explicitly |

The functional scope is the public CUTLASS varlen NA 1-D/2-D/3-D interface, and results on the current device cover only its CUDA runtime architecture. Other architectures and very large int32 entity allocations must be listed separately as not executed, never counted as passing. Out-of-bounds memory and synchronization are checked through compute-sanitizer's own entry points, and a missing or unrun tool is accounted for just as explicitly.

## Three layers of readings

1. **Strict capability checks**: document isolation, unreachable gradients, single-key identity, deterministic replay, packed versus isolated, document reordering and empty documents. Zeros and bitwise equality are judged strictly; the packed-versus-isolated comparison is relaxed only for the documents whose lowering genuinely differs, and the criterion and per-document adjudication go into `packed_vs_isolated_adjudication`. A failure keeps the raw error, the document position and the reproduction arguments rather than swallowing them under one atol.
2. **Independent numerical reference**: starting from the same inputs already quantized to the target dtype, the neighborhood, softmax and autograd are constructed explicitly on the CPU in FP64, calling none of NATTEN's mask, fixed or backward code. Maximum error, RMS error, reference norm and non-finite counts are recorded per tensor for O/LSE/dQ/dK/dV, along with independent FP32 arithmetic's error against FP64. These are numerical diagnostics: an FP32 reference error is not passed off as a general error bound for a BF16 kernel, and a small error does not declare a pass by itself.
3. **Efficiency**: identical inputs, dtype, geometry, determinism policy and upstream gradient, with the packed call versus the per-document calls as the only variable. Each workload keeps its strict correctness status, and speed cannot offset an error. Real token throughput, cold layout cost, warm forward, warm forward+backward, total time from packing to output, peak incremental memory, and kernel and copy operation counts are reported separately. Correctness is adjudicated per document under the same rule the capability cases use (see Packed versus isolated comparison splits by lowering): documents whose isolated call lowers differently are bounded by the FP64 reference interval or the kernel single-key gate, and the rest bitwise. The reference is built one document at a time -- documents share no edges, so each document's reference is the same quantity the whole pack gives, while the token count no longer enters the dense score matrix squared. A nondeterministic load (multiple KV splits) leaves no bitwise standard for the documents that would otherwise carry one, so the packed and per-document calls are each run twice as an A/A instead: that document's O, LSE, dK and dV must be bitwise identical across all runs, and dQ's largest cross-mode difference (in each element's own dtype ULP) must not exceed the larger A/A maximum plus one ULP; documents with a differing lowering in the same load still take the reference interval. The per-document adjudication goes into `packed_vs_isolated_adjudication`.

The old fixed path is a compatibility comparison only. Shared bugs are exposed by the independent reference and the known answers. The whole output is not compressed into one score, and passing the strict checks does not mean general floating-point error has been attributed.

## Self-checks

The reference is validated on hand-computed neighborhoods first: causal prefixes, shifted boundaries, even windows, stride, dilation, `kernel_size = 1`, effective window clamping and multi-axis Cartesian products. Single-key rows, the zero-logit mean and GQA gradient summation are validated, and the backward is checked by FP64 finite differences.

Fault injection covers four distinct mechanisms: deliberately opening a future edge, deliberately connecting two documents, restoring document order wrongly, and overflowing a low-precision dot product. Each must be caught by the corresponding check, and the correct reference must pass those same checks. The per-document comparison rule has self-checks of its own: a document with a length-1 axis inside a mixed pack is judged to have a differing lowering, a fully degenerate uniform pack is judged to take the identity path, and a fully degenerate document inside a heterogeneous pack is judged by the kernel single-key gate; a one-ULP drift must be caught on a bitwise document and must be admitted on a document with a differing lowering; the single-key document gate is controlled both ways with residuals planted at 0.5 and 500 times the bound. Performance adjudication is self-checked separately: a deterministic load reuses the same per-document classification, while a nondeterministic one only replaces the would-be bitwise documents with the repeat-calibrated noise scale, so a cross-mode drift the repeats reproduce is admitted and the same drift they do not reproduce fails. Performance statistics use the same function A/A as the zero-effect control and added real GPU work as the positive control. Case seeds are kept separate from reference self-check seeds.

## Performance design

Scenarios are chosen by load type: uniform videos, image-heavy packs, video-heavy packs, long-tailed lengths, dense short documents, grouped and interleaved permutations of the same composition, spatial layers, temporal layers, 3-D layers, degenerate spatial axes, and the mixed shapes from the downstream migration guide. Each scenario compares two ways of executing the same data only; a speedup is never claimed from two batches with different token counts.

A warm call reuses the layout; a cold call rebuilds it; the end-to-end packed call counts the time to concatenate Q/K/V. CPU wall time and CUDA event time spans are recorded separately, and the profiler samples outside the timed region, so the two are never conflated into pure kernel time. Memory statistics include this process's live tensor baseline and its peak increment.

Sampling alternates A/B and B/A in pairs, with the same function A/A calibrating that run's noise. All samples are kept, and the median, the paired difference and a bootstrap interval are reported; the fastest sample is not taken and slow samples are not dropped. GPU UUID, runtime capability, SM count, torch and CUDA versions, source diff and binary hashes are recorded; other GPU processes are checked before and after timing, and contention marks the reading invalid. Under virtualization a GPU client PID can differ from the host PID, so the runner saves the client list before and after CUDA initialization to identify its own process; without a unique identification it gives no valid timing. Jobs on a development machine are not interfered with.

## Running it and what it produces

The reference and checker self-checks run first, then the capability cases and the existing execution and API tests, and the performance bench last. One failure does not stop the other independent capabilities from being recorded, and the final process exit code must reflect any failure. The report lists the total planned, and how many completed, failed, were skipped or errored; a crash partway through still leaves the per-item JSONL and the list of what did not complete.

Acceptance means the bench's positive and negative controls work, every capability has a runnable entry point, and the current implementation's failures are shown honestly. It does not mean the current NATTEN has passed a migration.

Run it from the repository root, with `natten` importable from a built extension in the Python environment (`PYTHONPATH=src` in a source tree, or an installed wheel). Give `--output` a directory that does not yet exist each time; an existing one is refused rather than overwritten.

```bash
CUBLAS_WORKSPACE_CONFIG=:4096:8 CUDA_VISIBLE_DEVICES=0 \
python scripts/bench_mixed_batch.py --mode properties --graph-seed 41011 \
--output <a directory that does not yet exist>
```

| Task | Arguments | Artifacts and usage boundary |
| --- | --- | --- |
| Generic properties | `--mode properties --graph-seed 41011` | The real-dtype gradient comparison, plus the default 24 graphs and six property classes; a different seed generates another batch of graphs, and the original geometries are written to `plan.json` |
| Reproducing one item | `--mode properties --graph-seed 41011 --case graph-1088301 --property connectivity` | `--case` and `--property` may be repeated; a case name must belong to the given seed's graph set |
| Fixed regressions | `--mode regressions` | 47 fixed entries: 44 regression cases, plus the compute-delta known answer, cross-layer layout reuse and the bench's own oracle self-check |
| Execution and API | `--mode contracts` | Includes a multi-GPU test and needs two visible devices; a single group can be selected with `--case execution` and the like |
| Efficiency | `--mode performance --samples 30` | 12 load types, keeping the A/B and A/A samples per stage; select a load with `--case` |
| Timing self-check | `--mode performance --case perf-downstream-throughput --samples 4 --performance-smoke` | Marked `SMOKE_ONLY`; not a performance result |
| Memory and synchronization | `--mode sanitizer` | Invokes compute-sanitizer's memcheck and synccheck separately, over a representative subset of the regressions |
| Main suites together | `--mode all` | Properties, regressions, execution/API and efficiency; sanitizer runs on its own |

Every mode above needs `--output`; `--list` shows the graph descriptors and test groups without running anything. For contracts or `all`, change the example's `CUDA_VISIBLE_DEVICES=0` to `0,1`. Performance uses the single device it records, and must not contend with other GPU work while it runs.

`summary.json` records the per-item results and what did not complete, and `results.jsonl` is written as each item finishes; `source/`, `bench-sha256.json`, `source.diff` and `environment.json` preserve the version actually run and the device it ran on. `FAIL`, `ERROR`, `NOT_RUN` and incomplete items never count as passing. A performance `MEASURED` only says a time was obtained; read `correctness_status` as well, which is `FAIL` for a deterministic load and `REVIEW` for a nondeterministic one as soon as any one document misses its criterion. Both return a nonzero exit code, and the per-document rule, interval occupancy, and the A/A and cross-mode ULP readings all go into `packed_vs_isolated_adjudication`.

Later kernel iterations must also check compiled resources and the profiler: the constraint is to keep the low-precision shared-memory tile while allowing in-register precision promotion. Record the current binary's static resource usage (register count, shared memory, spills) before changing a kernel, and compare item by item afterwards.
